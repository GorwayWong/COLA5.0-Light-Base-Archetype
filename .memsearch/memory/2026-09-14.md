- Codex: # ToLink vNext 后端架构与技术选型说明

## 1. 架构定位

ToLink vNext 采用单 Maven 模块、分层包结构的模块化单体架构。当前版本定位为后端基础工程，仅提供运行、持久化、缓存、安全和 AgentScope 接入边界，不包含业务 API、业务表和业务领域模型。

```text
org.xaspire.tolink
├── adapter          外部请求与适配层
├── application      用例编排与应用服务层
├── domain           业务模型与业务规则层
└── infrastructure   数据库、缓存及外部技术集成层
```

依赖方向遵循以下原则：

- `domain` 不依赖 `adapter`、`infrastructure` 或具体技术框架。
- `application` 面向用例编排，依赖领域抽象。
- `adapter` 负责接收外部请求并转换为应用调用。
- `infrastructure` 实现数据库、缓存及外部服务适配。
- MyBatis-Plus、Redis、AgentScope 和未来的 OSS 客户端均限定在 `infrastructure` 边界内。

## 2. 基础设施职责

PostgreSQL 是持久化事实的唯一来源，数据库结构仅通过 Flyway 管理。Redis 定位为缓存和短期状态存储，不承载不可恢复的业务事实，因此不作为主就绪条件。

Actuator 仅暴露 health 端点：

- liveness 不依赖 PostgreSQL 或 Redis。
- readiness 检查 PostgreSQL。
- 默认安全策略为 deny-all，仅放行健康检查。
- Swagger UI 和 OpenAPI 仅在 `dev` profile...
